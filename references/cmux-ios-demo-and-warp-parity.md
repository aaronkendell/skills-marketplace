## Part 1 — Show a live iOS Simulator tab in cmux

### Hard prerequisite, read it or Part 1 fails

`cmux` talks to the app over a Unix socket and **refuses connections from processes not started inside
cmux**:

```
Error: ERROR: Access denied - only processes started inside cmux can connect
```

So: **you must be running in a terminal surface inside cmux.** If you are in Claude Desktop, Terminal.app,
Warp, or a CI shell, stop and tell the user to relaunch you from a cmux tab. Verify first:

```bash
cmux identify --json
```

If that errors with "Access denied", you are outside cmux. Do not proceed; do not fall back to driving
Simulator.app with generic screen-control tools without saying so explicitly.

### Verified machine state (2026-09-05)

- Xcode **26.6** (build 17F113), `xcode-select -p` → `/Applications/Xcode.app/Contents/Developer`
- **Booted:** `iPhone 17` — UDID `526457FB-4309-47DF-9DA5-1080538EB3BD` — iOS **26.5**
- Also available (shutdown): iPhone 17 Pro `4883AD39-7B17-46C4-8A87-5687DFE472F3`, iPhone 17 Pro Max,
  iPhone 17e, iPhone Air, iPad Pro 13" (M5), iPad Pro 11" (M5), iPad mini (A17 Pro), iPad Air 13"/11" (M4), iPad (A16)
- cmux **0.64.22**

### Steps

```bash
# 0. confirm you are inside cmux
cmux identify --json
cmux list-workspaces

# 1. open a Simulator surface in a split next to the current terminal
cmux new-pane --type simulator --direction right --focus true
#    (alternative: cmux new-surface --type simulator --focus true)

# 2. see what cmux bound to that pane
cmux ios list --json
cmux ios context --udid

# 3. if it did not bind to the booted iPhone 17, bind it explicitly
cmux ios select 526457FB-4309-47DF-9DA5-1080538EB3BD

# 4. prove it is live and drivable, not a picture
cmux ios screenshot --out /tmp/cmux-ios-before.png
cmux simulator foreground                 # which app is frontmost
cmux simulator button HOME
cmux simulator swipe 0.5 0.8 0.5 0.2 20   # normalized coords, 20 steps
cmux simulator rotate landscape-left
cmux ios screenshot --out /tmp/cmux-ios-landscape.png
cmux simulator rotate portrait

# 5. show the automation depth that Warp has no answer for
cmux simulator accessibility | head -40   # native accessibility tree
cmux simulator event-log 20
cmux simulator permissions list
```

Then show the user `/tmp/cmux-ios-before.png` and `/tmp/cmux-ios-landscape.png`, and tell them plainly
what worked and what did not. Do not claim success for a step that errored.

### If you want to show it against the real app

Bagman's mobile app is at `~/repos/bokendell/golf/apps/mobile`. Do **not** start a build or a dev server
unless the user asks — check with them first, because dev servers here are branch-isolated
(`swarm workspace dev`) and there are documented port-collision and Metro-cache traps. Showing the

### The point to make to the user afterwards

The whole `cmux simulator` surface — `type`, `tap`, `gesture` (1–256 ordered normalized touch events),
`multitouch`, `swipe`, `button`, `rotate`, `permissions grant/revoke/reset`, `camera`, `accessibility`,
`memory-warning`, `event-log`, `ca <diagnostic>`, `ui get/set`, and Web Inspector `targets`/`attach`/
`send`/`highlight`/`release` — is synchronous (*"Each command waits for its correlated Simulator-worker
result"*). **Warp has none of this.** In Warp you would run `xcrun simctl` in a shell, which is
Terminal.app parity, not a feature.

## Part 2 — Give cmux the Warp features worth having

The user's ask: *"I don't need to go to Warp, just have the stuff Warp has."* So build it. Everything
below is achievable with cmux's own extension points. Do the cheap high-value ones first and show
results before going further.

### The extension points you have

Run these to read the contracts before writing anything:

```bash
cmux docs sidebars     # runtime-interpreted SwiftUI-style custom sidebar in ~/.config/cmux/sidebars/ (beta)
cmux docs dock         # custom right-sidebar terminal controls from .cmux/dock.json or ~/.config/cmux/dock.json
cmux docs agents       # agent hooks, Feed approvals, notifications, session restore
cmux docs api          # CLI/socket API + the cmux agent skill
cmux docs settings     # cmux.json schema; note ~/.config/cmux/cmux.json is currently the untouched template
curl -fsSL https://raw.githubusercontent.com/manaflow-ai/cmux/main/skills/cmux/SKILL.md
curl -fsSL https://raw.githubusercontent.com/manaflow-ai/cmux/main/docs/cli-contract.md
curl -fsSL https://raw.githubusercontent.com/manaflow-ai/cmux/main/web/data/cmux.schema.json
```

Back up `~/.config/cmux/cmux.json` to a timestamped `.bak` before editing it — cmux's own CLI help says
to. Use `cmux config doctor` and `cmux reload-config` (reloads both cmux.json and Ghostty config in
place, no restart).

### Gap 1 — Rich tab metadata (Warp's biggest win). HIGH value, LOW effort.

Warp Expanded density shows per row: git branch, worktree path, **diff stats**, **PR badge**, agent
status. cmux shows branch + notification status.

cmux gives you the write side already:

```bash
cmux set-status <key> <value> --icon <name> --color '#hex' --priority <n>
cmux list-status
cmux clear-status <key>
cmux set-progress <0.0-1.0> --label <text>
cmux workspace-action --action <name> --title <text> --color <name|#hex> --description <text>
cmux rename-tab <title>
```

Build a small script — TypeScript in `scripts/`, not a bash one-off, per the repo convention — that for
the calling workspace computes `git branch --show-current`, `git diff --shortstat`, and
`gh pr view --json number,state,isDraft` (tolerate no-PR), then pushes them as statuses. Wire it to run
on agent turn boundaries via `cmux hooks` (see `cmux docs agents`) and/or a `Stop`/`PostToolUse` hook in
`~/.claude/settings.json`. Result: diff stats and PR state visible in the cmux sidebar, which is the
single thing the user envied about Warp.

### Gap 2 — Tab Configs equivalent. HIGH value, MEDIUM effort.

Warp: TOML files in `~/.warp/tab_configs/` with panes, `commands`, `repo`/`branch` param pickers,
`{{autogenerated_branch_name}}`, launched from a `+` menu or `warp://tab_config/<name>`.

cmux has the primitives:

```bash
cmux new-workspace --name <title> --description <text> --cwd <path> --command <text> --layout <json> \
                   --group <ref> --group-placement afterCurrent --focus true
cmux new-split <left|right|up|down>
cmux new-surface --type <terminal|browser|simulator|agent-session> --provider <codex|claude|opencode>
cmux open <path-or-url>
cmux todo add ...
```

Write a `lane` command (TS, in `scripts/` or as a swarm-cli subcommand — the repo says repeatable scripts
belong there, never bash one-offs) that reads JSON lane definitions from `~/.config/cmux/lanes/*.json`
and materialises a workspace: create the worktree, generate the branch name, split panes, start
`claude` in one and a shell in the other, run the `swarm workspace dev` bring-up, set the workspace title
and colour. Give it a `--repo`/`--branch` prompt when args are missing. That is Tab Configs, with the
advantage that it can also do the worktree and workspace wiring the user already does by hand.

Note the existing `.worktrees/` convention and the documented traps before wiring bring-up: one workspace
owns port 3110 at a time, and `swarm workspace dev` is a single invocation covering all apps.

### Gap 3 — A Warp-style sidebar. MEDIUM value, MEDIUM effort, highest ceiling.

`cmux docs sidebars` describes a **runtime-interpreted SwiftUI-style file in `~/.config/cmux/sidebars/`
(beta)**. This is the escape hatch that makes the whole "have the stuff Warp has" ask tractable: you can
author a custom sidebar that renders exactly Warp's expanded row — icon, title, cwd, branch, diff stats,
PR badge, status colour — reading from `cmux list-status` / `cmux tree --all --json`. Read the docs, build
the smallest version that renders one row correctly, show the user, then iterate. Also read
`cmux docs dock` for right-sidebar controls (`.cmux/dock.json`) — cheap buttons for common lane actions.

### Gap 4 — Search across tabs by branch / PR / diff. LOW effort.

Warp filters tabs *"by title, working directory, Git branch, PR label, or diff stats."* cmux has
`cmux find-window [--content] [--select] <query>`. Once Gap 1 puts branch/PR/diff into titles or
statuses, `find-window --content --select` covers most of it. Check whether it searches status values; if
not, encode the key facts into the tab title via `rename-tab`.

### Gap 5 — Code review with inline comments back to the agent. MEDIUM value.

cmux already has `cmux diff --source last-turn|unstaged|staged|branch --layout split|unified`, which is
turn-scoped and arguably better-targeted than Warp's panel. What Warp adds is inline comments routed to
the running agent. Approximate it with `cmux send --surface <agent-surface> "<comment>"` driven from a
review script. Do this one last; it is the least broken thing today.

### Do NOT build

- A Warp Agent equivalent. The user runs Claude Code and pays for Max 20x; a second agent is waste.
- Cloud VM orchestration. cmux Pro ($40/mo annual) covers it and the user is not buying it.
- Anything that requires a paid tier of anything.

### Ground rules from this repo

- No auto-commit. Stage with `git add`; the user commits.
- `--no-verify` on commits and pushes.
- Repeatable work is TS in `scripts/` or a swarm-cli command, never a bash one-off.
- Fix lint properly; no `biome-ignore`.
- Report honestly: if a cmux command errors or a gap turns out not to be closable, say so rather than
  narrating a partial success as done.

## Appendix — the unified cloud-session question, answered

The user asked whether there is one UI to see and launch **both** Cursor cloud agents and Claude Code
cloud sessions. **No. There is not, as of 2026-09-05.**

- **`claude agents`** (Agent View) — Anthropic's CLI dashboard, research preview launched **2026-05-11**,
  requires Claude Code v2.1.139+, available on Pro/Max/Team/Enterprise/API. Single list of all parallel
  sessions with status, elapsed time, sorting and filtering. **Claude Code only, and local sessions** —
  it is explicitly not available inside Cursor.
- **Cursor** has its own background/cloud agents, reachable from Cursor desktop, web, mobile, Slack and
  GitHub. Separate surface, separate pool.
- **Warp Oz** is a genuine cloud-agent console with a mobile-friendly web app — but it only shows runs
  **Warp** launched, and its Claude Code harness is API-key funded, not subscription funded.
- **Conductor** (conductor.build) runs Claude Code, Codex *and* Cursor in one app — but the free tier is
  **local workspaces only**; cloud workspaces and the API are Pro at **$50/mo**. So it is the closest
  thing to a unified launcher, and the unified part is the paid part.
- No third-party dashboard aggregating Cursor cloud agents + Claude Code cloud sessions was found.

**The one surface where they already converge is GitHub.** Both open pull requests — the user's Cursor
agents produced golf PRs #74, 75, 76, 77, 78, 81, 82, 84 on `cursor/*` branches. So the practical unified
view today is `gh pr list` / the GitHub PR page, plus `claude agents` for Claude-side detail. If a single
pane of glass is genuinely wanted, the cheap build is a script that merges `gh pr list --json` with
`claude agents` output and renders it in a cmux sidebar or dock — which is Gap 3 above with a different
data source, not a new product.
